# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Grace period logic bug: difference is floored to integer minutes before checking `minutes > 10`. Any punch-in between 10:01 and 10:59 after shift start yields `minutes = 10`, making `minutes > 10` evaluate to `False` and returning 0 late minutes instead of 10. | Punch-in at 09:40:01 for a 09:30 shift returns 0 late minutes instead of 10, violating R2. | Check `diff_seconds > 600` strictly in seconds before computing `int(diff_seconds // 60)`. |
| 2 | `compute_late_minutes` (lines 33-37) | Timezone naive and overnight shift unaware: `punch_in.replace(...)` assumes local naive datetime and doesn't handle overnight shifts where a punch-in after midnight belongs to a shift starting on the previous calendar day. | Overnight punch-in at 00:30 IST for a 22:00 shift sets start to 22:00 on the same day (future), returning negative late minutes. | Convert `punch_in` to IST and compute shift start datetime relative to the attendance date determined by R1. |
| 3 | `compute_overtime` (lines 44-48) | Missing 30-minute threshold: computes `max(0, int((punch_out - end).total_seconds() / 60))`, awarding overtime for any minute worked past shift end without checking the minimum threshold. | Punch-out at 18:35 for an 18:30 shift end awards 5 minutes overtime instead of 0, violating R3. | Check `diff_seconds >= 1800` (30 minutes); return 0 if less. |
| 4 | `compute_overtime` (lines 44-48) | Overnight shift handling and timezone mismatch: sets shift end on `date_str`, but for overnight shifts (`shift_end <= shift_start`), the shift ends on the next calendar day (`date + 1`). Also mixes offset-aware `end` with naive `punch_out`, causing `TypeError`. | Overnight shift (22:00 - 06:00) computes 24+ hours overtime or crashes with `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Set shift end on `date + 1 day` for overnight shifts in IST, ensuring consistent timezone-aware subtraction. |
| 5 | `compute_work_hours` (lines 40-41) | Incorrect rounding mode: uses Python's `round()`, which applies round-half-to-even (banker's rounding) instead of round-half-up specified by R4 and R8. | Test input resulting in 4.495 hours rounds down to 4.49 instead of rounding up to 4.50. | Use Python's `Decimal` with `ROUND_HALF_UP` quantization to 2 decimal places. |
| 6 | `GET /health` (lines 72-74) | No database readiness check: unconditionally returns `{"status": "ok"}` with 200 without verifying MongoDB connectivity. | `/health` returns 200 even when MongoDB is stopped or unreachable, failing readiness probe contract. | Ping MongoDB via `client.admin.command('ping')` and return 503 if unavailable. |
| 7 | `POST /employees` (lines 79-83) | Check-then-insert race condition: checks `find_one` then calls `insert_one` without a database unique index constraint. Two concurrent creates both pass the check. | Concurrent POST requests with the same `emp_code` create duplicate records or fail race tests. | Create a unique index on `emp_code` at startup and catch `DuplicateKeyError` to return 409. |
| 8 | `POST /employees` (lines 53-61, 77-85) | Missing schema and contract validation: `emp_code` regex (`^EMP\d{4,6}$`), email format, string lengths, and `shift_start != shift_end` rule were not validated. | Sending invalid `emp_code` ("INVALID"), invalid email, or `shift_start == shift_end` returns 201 instead of 422. | Added Pydantic field validators with exact regex constraints and a check that `shift_start != shift_end`. |
| 9 | `POST /employees` (lines 82, 85) | Invalid serialization of `created_at`: stores naive `datetime.now()` and returns an ISO string instead of integer epoch milliseconds. | Client receives an ISO string timestamp, violating the OpenAPI schema requiring an `int64` epoch milliseconds. | Store UTC datetime in MongoDB and serialize to integer epoch milliseconds in API response. |
| 10 | `GET /employees` (lines 93-95) | Off-by-one pagination bug: calculates `skip = page * page_size`. When `page=1`, it skips 20 records and begins at record 21, omitting the first page. | Calling `GET /employees?page=1&page_size=20` returns page 2 items instead of page 1. | Correct skip formula to `skip = (page - 1) * page_size`. |
| 11 | `GET /employees` (lines 94-95) | Total count ignores filter, and missing sort: `total` counts the whole collection (`count_documents({})`), and results are not sorted by `emp_code` ascending. | Filtering by department returns total count of all employees, and items are unordered. | Use `db.employees.count_documents(q)` and add `.sort("emp_code", ASCENDING)`. |
| 12 | `POST /attendance/punch-in` (lines 101, 113) | Missing employee existence check: if employee is not found, accessing `emp["shift_start"]` raises an unhandled `TypeError` (500). | Punch-in with non-existent `emp_code` yields 500 Internal Server Error instead of 404 Not Found. | Check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 13 | `POST /attendance/punch-in` (lines 104-118) | Punch-in race condition: check-then-insert allows concurrent duplicate punch-ins for the same employee and date. | Simultaneous punch-in requests at the same millisecond insert duplicate attendance documents. | Add compound unique index on `("emp_code", 1), ("date", 1)` and catch `DuplicateKeyError` to return 409. |
| 14 | `POST /attendance/punch-in` (lines 102-103) | Timezone and overnight shift date bug: uses server local timezone instead of IST; does not attribute overnight shifts punched in before `shift_end` to the previous calendar day. | Server running in UTC assigns UTC date instead of IST; overnight punch-in at 00:30 IST gets current day instead of yesterday's shift date. | Parse instant to IST and assign attendance date to previous calendar day when punch-in is earlier than `shift_end` on overnight shifts. |
| 15 | `POST /attendance/punch-in` (lines 119-121) | Leaking internal ID and unformatted datetimes: sets `"id": str(res.inserted_id)` and returns raw datetime objects. | Response contains forbidden `"id"` field and unformatted dates instead of epoch milliseconds. | Remove internal ID and serialize `punch_in` as epoch milliseconds integer. |
| 16 | `GET /attendance` (lines 144-147) | Severe scalability defect: loads the entire collection into memory (`list(db.attendance_logs.find(q))`) and sorts in Python; misses secondary sort by `emp_code` ascending. | At 100,000 records, the endpoint runs out of memory or times out; query plan is a COLLSCAN. | Use MongoDB index-backed `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` and `count_documents(q)`. |
| 17 | `GET /attendance` (lines 136-141) | Missing date range validation: does not validate `date_from <= date_to`. | Querying `date_from > date_to` returns an empty list with 200 instead of returning 422. | Added validation returning 422 when `date_from > date_to`. |

Also note anything you looked at and decided was **not** a defect, and why:
- `IST = timezone(timedelta(hours=5, minutes=30))` definition: Indian Standard Time has a fixed offset of UTC+05:30 with no daylight saving time transitions, making this definition accurate and reliable.
- Status values stored as uppercase strings (`PRESENT`, `WFH`, `ON_DUTY`, `ABSENT`, `LEAVE`): Matches the data model contract in `DATA_MODEL.md`.
- Setting `punch_out`, `work_hours` to `None` and `overtime_minutes` to `0` at punch-in: Correct per specification since an open punch-in record cannot have work hours or overtime until the employee punches out.
- Empty `history: []` initialized on punch-in: By design, `history` is an audit trail exclusively for manual corrections (PATCH regularizations) and is never populated during punch-in or punch-out.
